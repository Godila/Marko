# Наборы (sets) в Нацкаталоге — дизайн фичи

Дата: 2026-09-22. Статус: дизайн v2 (правка по фидбеку юзера — добавлены xlsx-импорт,
сценарии «компоненты не заведены» и анти-дубли), реализации пока нет.
Пайплайн: /feature-dev (explorer→architect→TDD→reviewer).

## 1. Задача и домен

Юзер (YCPB, лёгпром, WB FBS) продаёт наряду с единицами товара **наборы** — чаще всего
«шапка + шарф». Набор = самостоятельный товар со **своим GTIN**, маркируется **одним кодом
(КИН)** на упаковку. Это НЕ комплект (у комплекта свой ТНВЭД-критерий 6302/6103/6104/6203/6204,
производитель задаёт при производстве, не разбирается; шапка+шарф под комплект не подходит).

Требования юзера:
1. Набор собирается **из уже существующих опубликованных карточек** (наши GTIN).
2. **Два равноправных пути создания: UI-конструктор И импорт из xlsx** (оператор заполняет
   GTIN/артикулы компонентов прямо в файле).
3. Проработать сценарий «компоненты набора ещё не заведены в НК» и обратный — и
   **не создавать дубли** ни наборов, ни компонентов.

## 2. Живой ресерч API (прод-проба 22.09 + доки docs.crpt.ru / markirovka.ru)

### 2.1 Проверено живьём на проде (read-only, токен из platform.kv mt_token)

`GET {mt_base_v3}/nk/attributes?tnved=6505009000&is_set=true` — работает, возвращает
**атрибутный состав карточки набора лёгпрома — всего 6 атрибутов** (против ~12 у обычной
карточки; нет вида товара/размера/цвета/состава-тканей/декларации 23557/производителя):

| attr_id | Название | Тип | Обяз. |
|---|---|---|---|
| 2478 | Полное наименование товара | text | m |
| 2504 | Товарный знак | text | m |
| 3959 | Группа ТНВЭД | text (preset) | m |
| 23768 | Товарная группа | text (preset) | m |
| 16271 | **Состав набора** (текст немаркируемых вложений) | text | r |
| 23821 | **Количество маркированных товаров в наборе** | number | r |

`GET /nk/product?gtin=<gtin>` — работает, в ответе есть `is_set`, `is_kit`, `set_gtins[]`,
`good_status` (в т.ч. `archived`), `good_mark_flag`, `identified_by` — канал чтения наборов
из ЧЗ для «Проверить в ЧЗ» и для проверки внешних компонентов.

### 2.2 Создание набора — обычный фид

`POST /nk/feed`, entry дополнительно к обычным полям несёт:
`is_set: true`, `set_gtins: [{gtin, quantity}, ...]` («указывается только с is_set=1»),
`is_kit` — для комплектов (не наш случай). Предел: ≤1000 GTIN в наборе (иначе 413), фид
≤500 товаров / ≤25 МБ. Лёгпром-нюанс: `set_gtins[].gtin` для ТГ «лёгпром» **не обязателен**
— состав можно задать только количеством (23821); при пустых привязках в КИН допускаются
любые GTIN в количестве из карточки (правило SETS_AGGREGATION).

Ответ `{result: {feed_id}}` → `GET /nk/feed-status` → модерация (`GET /nk/feed-moderation`)
→ подписание `feed-product-document` (≤10) + УКЭП → `feed-product-sign-pkcs` — **весь
существующий конвейер МАРКО переиспользуется без изменений** (worker `nkmt_cycle` тоже).

### 2.3 GTIN набора

`GET /nk/generate-gtins?quantity=N` — тот же метод (в МАРКО уже есть), 13 цифр → zfill(14),
monthly-limit 11000. «Наборности» в методе нет — тип задаётся карточкой (`is_set`).

### 2.4 Дальний контур (фаза 2, НЕ входит в фичу)

- СУЗ: заказ на GTIN набора, `cisType: "SET"` (справочник типов упаковки: UNIT/SET/BUNDLE).
  СУЗ-контура в МАРКО нет вообще — отдельная будущая фича.
- Формирование КИН: документ ГИС МТ `SETS_AGGREGATION` (unitSerialNumber=КИН,
  sntins=КИ вложений; карточки компонентов должны быть published; после агрегации набор
  автоматически вводится в оборот; продажа/чек = авторасформирование и вывод КИН).
- WB: штрихкод карточки WB = GTIN набора. **Гейт-неизвестность**: отдаст ли WB КиЗ на
  заказ набор-листинга корректно (SET). Первый живой набор-заказ покажет; если нет —
  фаза 2 (СУЗ) становится обязательной.

## 3. Решения (допущения вместо уточняющих диалогов — юзер пропускает)

1. **Два пути создания поверх одной модели** (§5.1): UI-конструктор (разовые наборы,
   максимум удобства) И xlsx-импорт (массово, оператор сам заполняет компоненты).
   Оба проходят один preview→создание→конвейер.
2. **Режим по умолчанию — привязанный набор** (set_gtins с конкретными GTIN): честное
   соответствие карточка↔состав↔WB-листинг (каждому сочетанию цветов свой GTIN = свой
   штрихкод WB). Режим «без привязки» (только количество 23821) — опция: в конструкторе
   чекбокс, в xlsx строкой без компонентов.
3. **Ссылка на компонент: артикул ИЛИ GTIN** (приоритет — наш каталог): значение ячейки
   ищется как article в nkmt.cards; не найдено и 13-14 цифр → внешний GTIN; иначе ошибка.
   Артикул решает сценарий «компонент ещё не опубликован / GTIN ещё не сгенерирован» —
   набор-черновик ссылается на карточку компонента заранее.
4. **«Компоненты не заведены в НК» — двухфазный гард**: создать набор-черновик можно с
   предупреждением (статусы компонентов видны в preview); **подача фида гардится** —
   наши компоненты должны быть published с GTIN, внешние — находиться в НК (/nk/product).
   Естественный флоу: импорт карточек компонентов → импорт наборов → подача.
5. **Анти-дубли, четыре слоя** (§5.5): идемпотентность по артикулу; точный дубль состава
   (мультимножество gtin×qty) = блок; GTIN набора — существующая логика new/update/conflict;
   набор-в-набор = блок (ЧЗ: в лёгпром-набор вкладываются только UNIT/BUNDLE).
6. **UI живёт в «Каталоге НК»** как таб-чип «Наборы» (паттерн табов как в Справочниках):
   внутри — карточка «Импорт наборов» (файл + шаблон) и кнопка «Собрать набор…».
7. **Правка до подачи** — конструктор в режиме edit / повторный импорт той же строки
   (update по артикулу); **после подачи — read-only** (состав опубликованного набора менять
   нельзя — риск несоответствия КИН карточке; «Собрать аналог» покрывает вариации).
8. **Статусы не расшираем** (DESIGN.md §8): CARD_STATUS/BATCH_STATUS как есть. `archived`
   из /nk/product показывается текстом в drawer без нового бейджа.
9. Декларация/производитель набору не нужны — их нет в атрибутном составе набора (проверено
   живьём §2.1); РД остаются на компонентах. Правила/дефолты НКМТ (RULE_FIELDS, resolve)
   не трогаем — они для xlsx-импорта обычных карточек.

## 4. Подходы (рассмотренные)

- **A. Одна модель + два входа: конструктор И xlsx-импорт (ВЫБРАНО)**: `cards.is_set` +
  `nkmt.set_items`, конструктор-мастер и отдельный шаблон наборов поверх общего
  preview/батчей/конвейера. Максимальное покрытие сценариев юзера, дедуп в одном месте.
- **B. Только конструктор без xlsx (отвергнут по фидбеку юзера)**: разовые наборы удобны,
  массовый ввод и «оператор сам заполняет GTIN в файле» — нет.
- **C. Только реестр чужих наборов без создания (отвергнут)**: задачу не решает; чтение
  из ЧЗ вошло в A как «Проверить в ЧЗ».

## 5. Архитектура (фаза 1)

### 5.1 Модель (миграция 0019)

```
ALTER TABLE nkmt.cards ADD COLUMN is_set BOOLEAN NOT NULL DEFAULT FALSE;
CREATE TABLE nkmt.set_items (
  id SERIAL PRIMARY KEY,
  card_id INTEGER NOT NULL REFERENCES nkmt.cards(id) ON DELETE CASCADE,
  gtin VARCHAR(32) NOT NULL,          -- GTIN компонента (резолв артикула на подаче)
  quantity INTEGER NOT NULL CHECK (quantity > 0),
  UNIQUE (card_id, gtin)
);
```
Набор = Card(is_set=true) в Batch. Конструктор — батч из 1 набора; xlsx-импорт — батч
из N (source_filename = файл, ≤500 как у карточек). Обычные списки карточек фильтруют
`is_set=false`, список наборов — `is_set=true`. FK на компонент не делаем (компонент может
быть внешним GTIN); ссылка по артикулу хранится резолвом в gtin на подаче — для ещё без-GTIN
компонентов gtin временно = пусто НЕ может (NOT NULL)... поэтому ссылка на наш компонент
хранится как article в отдельном поле `nkmt.set_items.article_src` (резолвится в gtin при
подаче; если задан gtin — поле пусто). UNIQUE(card_id, gtin) → скорректировано:
UNIQUE(card_id, COALESCE(NULLIF(gtin,''), 'src:'||article_src)) — выражением, либо простая
проверка дубликатов в сервисе (выбрано: проверка в сервисе, без функционального индекса).

### 5.2 Сервис

- `service._feed_entry(card)`: при `is_set` строит entry c `is_set:true`,
  `set_gtins:[{gtin, quantity}]` (привязанный режим; gtin компонентов резолвятся из
  article_src → карточка → gtin на момент подачи) и good_attrs
  `[2478 name, 2504 brand, 23821 итого-предметов, 16271 состав-текст (если дан)]`;
  3959/23768 не шлём (preset, НК выводит из tnved — сверить на первой живой подаче).
- **Гард подачи наборов** (в feed_batch перед отправкой): для каждого набора батча —
  компоненты наши: gtin есть и карточка published, иначе набор НЕ отправляется (остаётся
  в батче, попадает в ответ «пропущен: причина»); компоненты внешние: наличие в НК через
  `/nk/product` (кэш kv `nk_products:{gtin}`, TTL 24 ч); `is_set` у компонента = блок.
  Отправляются только валидные; если невалидны все — 400 со списком причин.
- `parse.SPEC_SETS` — колонки шаблона наборов (§6.2) + генератор шаблона с листом
  «Инструкция» (паттерн шаблона карточек).
- Кэш атрибутов: `nk_attrs_set:{tnved}` (dicts.attrs_model обобщить параметром is_set;
  NkClient.attributes получает `is_set: bool | None = None` → param `is_set=true`).
- `NkClient.product(token, gtin)` — GET /nk/product («Проверить в ЧЗ» набора, проверка
  внешних компонентов; живьём проверено 22.09).
- Генерация GTIN набора — существующая логика feed_batch (пустой gtin → generate-gtins).

### 5.4 Валидации (общие для конструктора и импорта)

- Состав: ≥1 компонент (привязанный режим); дубли ссылки (gtin или article_src) — блок;
  сумма количеств ≤1000 (413 ЧЗ); qty ≥1.
- Разыменование ссылки: article найден в наших cards → компонент «наш» (статус виден);
  не найден и 13-14 цифр → внешний GTIN (проверка в НК — сеть, кэш); иначе — ошибка
  «не артикул и не GTIN».
- Наши компоненты: `published` + gtin → ✓; иначе ⚠ «ещё не опубликован — набор можно
  сохранить черновиком, подача подождёт» (создание) / блок (подача). Внешние: найден в
  НК → ✓ (имя из НК); не найден → ⚠ в preview, блок на подаче; `is_set=true` → блок
  (набор в набор нельзя).
- Unbound-режим: 23821 вручную (≥1); привязанный: 23821 = Σ quantity (readonly, авто).
- ТНВЭД набора: пусто в xlsx → ТНВЭД первого резолвленного компонента; предупреждение
  при разных ТНВЭД компонентов (GS1 — одна категория).
- Наименование: пусто → авто «Набор: {имя1} + {имя2}» (если имена резолвятся; для
  полностью внешних — обязательно заполнить); article: в xlsx обязателен, в конструкторе
  авто `SET-####`.
- Удаление/правка — только пока не подан.

### 5.5 Анти-дубли (четыре слоя)

1. **Идемпотентность по артикулу**: повторный импорт строки с существующим article
   набора = update этого набора (поля+состав), не дубль (до подачи). Конструктор при
   совпадении article — ошибка «занят» (article UNIQUE, как у карточек).
2. **Точный дубль состава**: существует набор с тем же мультимножеством (gtin×qty,
   gtin-резолвы учтены) в незавершённом статусе → **блок** с указанием на существующий
   (article/gtin/название). «Кроме себя» при правке. Termинированные (удалённые) не считаются.
3. **GTIN набора**: если оператор указал GTIN набора сам — существующая логика plan_batch
   `new|update|conflict` («gtin занят»); пусто → генерация при подаче.
4. **Набор в набор**: компонент сам является набором (наш is_set или is_set из НК у
   внешнего) → блок (регуляторно: только UNIT/BUNDLE).

Обратный сценарий «компоненты уже заведены» дубли не создаёт по построению: импорт
наборов НЕ создаёт карточки компонентов — только ссылается (создание компонентов =
обычный шаблон карточек со своим gtin-планом new/update/conflict).

## 6. UX/UI (DESIGN.md §7, без новых статусов/цветов)

### 6.1 Каркас

«Каталог НК» → таб-чипы «Карточки | Наборы». Таб «Наборы»: карточка «Импорт наборов»
(выбор файла → превью-модалка → апрув; ссылка «Скачать шаблон»), кнопка «Собрать набор…»,
пусто-состояние «Соберите первый набор из опубликованных карточек или импортируйте
шаблон», грид.

### 6.2 Шаблон xlsx «Наборы» (лист «Наборы» + лист «Инструкция»)

| Колонка | Обяз. | Прим. |
|---|---|---|
| Артикул | да | ключ идемпотентности; повтор строки = update |
| Наименование | нет | пусто → авто из имён компонентов |
| Бренд | нет | пусто → дефолт (YCPB) |
| ТН ВЭД набора | нет | пусто → ТНВЭД 1-го компонента; warn при разно-ТНВЭД |
| GTIN набора | нет | пусто → генерация при подаче; заполнен → new/update/conflict |
| Компоненты | да* | `АРТИКУЛ|GTIN×кол-во; …` — разделитель «;», количество после ×/x/X/* (умолч. 1); приоритет резолва — артикул из нашего каталога, затем GTIN; «*» = обязательна ЛИБО эта колонка, ЛИБО «Кол-во предметов» |
| Кол-во предметов | да* | только для строк без компонентов (unbound-набор) |
| Состав (немаркируемые) | нет | текст → attr 16271 |

Превью импорта (модалка .modal.wide, паттерн ImportPreview карточек): построчная таблица
с резолвнутыми компонентами (чипы «имя ×N», статусы ✓/⚠/✗), колонка «Результат»
(ок / ошибки red / предупреждения amber), счётчики, кнопки «Импортировать N наборов» /
«Отмена». Сетевые проверки внешних GTIN — на превью (с кэшем).

### 6.3 Грид наборов

table.t.fit + colgroup (все ширины заданы, §7/§13): Артикул | GTIN набора | Название |
Состав (чипы-бейджи «{имя} ×N», EllCell-раскрытие при 3+, бейджи переносятся внутри
колонки) | Статус (CARD_STATUS). Строка кликабельна → drawer (паттерн DeclarationCard:
действия в карточке, не в строке).

### 6.4 Drawer набора

Состав списком (наши компоненты — ссылки на карточки и их статусы; внешние — gtin и имя
из НК; ещё не опубликованные — бейдж статуса компонента), атрибуты, статус конвейера,
кнопки по состоянию: до подачи — «Подать фид / Изменить / Удалить»; после — «Обновить /
Подписать / Проверить в ЧЗ» + hint «GTIN набора используйте как штрихкод карточки WB» +
«Собрать аналог» (мастер, предзаполненный текущим набором).

### 6.5 Мастер «Собрать набор» (модалка .modal.wide, 3 шага)

1. **Состав**: поиск по published-карточкам (article/GTIN/название), клик — добавить,
   выбранные — чипы с qty-степпером ±, счётчик «Итого предметов: N».
2. **Карточка набора**: наименование (авто), бренд, ТНВЭД (селект + warn), чекбокс
   «Не привязывать GTIN компонентов (собирать из любых остатков)» — при включении состав
   скрывается, 23821 вручную; «Состав набора» (текст немаркируемых, опц.).
3. **Проверка**: POST /sets/preview — ошибки (red) / предупреждения (amber) / сводка со
   статусами компонентов; свёрнутый тех-предпросмотр entry фида; «Создать и подать»
   (moderation:1, с гардом подачи) или «Создать черновик».

Правка = тот же мастер с предзаполнением (паттерн edit-режима справочников). Адаптив

## 9. Риски

- Состав после публикации неизменяем (вероятно) — read-only после подачи, «аналог» вместо
  правки. НЕ ПРОВЕРЕНО до первой живой подачи.
- WB может не уметь заказывать КиЗ типа SET на FBS → фаза 2 обязательна. Проверить первым
  живым набор-листингом.
- Пресет 23768/3959: если фид набора их потребует явно — добавить в _feed_entry по
  результатам фазы 0 (первая подача покажет ошибки фида в refresh).
- Неоднозначность «все-цифровой артикул vs GTIN» в колонке «Компоненты»: приоритет всегда
  за нашим каталогом (article-матч); если article не найден, а значение похоже на GTIN —
  оно трактуется как внешний GTIN (в превью это видно явно).
- Частичная подача батча (валидные ушли, невалидные ждут) — ответ и UI обязаны clearly
  показывать пропущенные с причинами, иначе «тихие» застрявшие наборы.
