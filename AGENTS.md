# AGENTS.md — координация агентов МАРКО

## Проект

FastAPI/SQLAlchemy/Postgres (пакет `marko`) + React-консоль (`ui/src/App.jsx` — монолит + `marko.css`).
Прод: https://marko.adel-factory.ru (домен светить можно, креды VM — нет).
Репо: github.com/Godila/Marko; после каждого коммита — push в origin.

**Стиль UI: `DESIGN.md` в корне — источник правды.** Перед любой правкой UI — сверка с ним;
чек-лист раздела 13 («Чек-лист перед коммитом UI») обязателен. Словари статусов не расширять молча.

## Роли

- **Главная модель**: бэкенд, архитектура, миграции, деплой, код-ревью, коммиты/push.
- **frontend-qa** (мультимодальный): «руки в браузере» — живые прогоны UI, скриншоты,
  console/network-ошибки, DOM-метрики, адаптив, E2E Playwright, правки UI по DESIGN.md.
- **vision-eyes**: «глаза» на готовые PNG-файлы (эталонная сверка вёрстки по DESIGN.md).
- **code-reviewer / code-explorer / code-architect**: ревью и разведка кода.

## Протокол frontend-qa

Когда звать: после каждой правки UI (живая валидация), визуальный/UX-аудит экрана,
E2E-сценарий, «посмотри, как выглядит фронт», frontend validation, Playwright-проверка.

Шаблон задачи обязательно включает:

1. **URL** (прод или локальный dev-сервер).
2. **Вход**: токен из `secrets/platform-token.txt` (ОДНА строка целиком).
   ЗАПРЕЩЕНО выводить значение токена в любых выводах/логах/комментариях (санитайзер `***`).
3. **Режим**: read-only по умолчанию; явный список запрещённых мутирующих кнопок
   («Собрать», «Подать», «Импортировать», «Подписать», «Удалить», «Сохранить», «Обновить»).
   Мутации — только по явному разрешению в конкретной задаче.
4. **Чек-лист**: целевые разделы, консоль, сеть, адаптив 900px, скриншоты.
5. **Скриншоты** → `C:\Users\geor\Desktop\marko-qa-screens\<дата>-<тема>\`.

Ограничения (проверено живым прогоном 08.09):
- Playwright MCP субагенту недоступен — сам ставит `playwright-core` во временную папку
  ВНЕ проекта и управляет headless Chromium через node-скрипты (Bash). Работает, не пачкать репо.
- **Без инструмента Read субагент НЕ ВИДИТ свои скриншоты** (его «визуальность» — DOM-метрики
  и пиксельная статистика). Поэтому после его прогона ВСЕГДА второй шаг:
  **vision-eyes на ключевые кадры с эталоном DESIGN.md**. Если Read добавят в конфиг
  субагента — шаг vision-eyes становится опциональным.

## Цикл UI-задачи (Definition of Done)

1. Правка по DESIGN.md → `npm run build` зелёный.
2. Прогон frontend-qa (read-only) → скриншоты.
3. Вердикт vision-eyes по скриншотам (наложения, обрезки без ellipsis, контрасты, пустые провалы).
4. Минорные дефекты — фикс до коммита; спорные — в отчёт юзеру.
5. Коммит + push в origin (деплой — по обычному процессу, сериализованно).

## Безопасность и координация

- Токены/креды — только файлы `secrets/`, никогда в чат/коммиты/репорты. `secrets/` в .gitignore.
- Скриншоты содержат данные прод-консоли — не публиковать наружу.
- Параллельные сессии: общие файлы перечитывать перед edit; `ui/src/App.jsx` — один писатель
  за раз; pytest и деплой строго сериализованы; чужие untracked-артефакты не трогать.
