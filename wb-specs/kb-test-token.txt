"Главная\n/\nТестирование и песочница\n/\nТестовый токен и песочница WB API\nТестовый токен и песочница WB API\nКогда нужен тестовый токен, как его создать и перейти к реальной работе\n\nДата обновления: 05.08.2026\n\nЧто такое тестовый токен\n\nТестовый токен — это специальный токен WB API, который предоставляет доступ только к тестовым данным, а не к реальной информации вашего магазина.\n\nТестовый токен работает в изолированной «учебной» среде (песочнице), где можно безопасно проверять интеграцию, не рискуя испортить реальные данные магазина.\n\nКлючевое отличие от других токенов\n\tТестовый токен\tСервисный / Персональный / Базовый\nДоступ к реальным данным\tНет\tДа\nРаботает с настоящими товарами и заказами\tНет\tДа\nСреда\tПесочница (тестовые данные)\tБоевая (реальные данные)\nНазначение\tРазработка и тестирование\tРеальная работа интеграций\nДля чего нужен тестовый токен\n\nДля разработчиков интеграций. Разработчик может писать и отлаживать код без риска изменить цены, создать дубли карточек или испортить данные заказов.\n\nДля изучения возможностей API. Можно экспериментировать с методами, изучать структуру данных, понимать возможности платформы.\n\nДля проверки обновлений. Если планируется обновление работающей интеграции, можно протестировать новые функции до запуска.\n\nКогда тестовый токен НЕ нужен\nПодключаете готовый сервис из Каталога решений для бизнеса на Wildberries → используйте Сервисный токен\nПодключаете собственную программу для реальной работы → используйте Персональный токен\nХотите протестировать на реальных данных → используйте Базовый токен\nТипичные ситуации: какой токен выбрать\nПодключение сервиса аналитики из Каталога решений\n\nНужен: Сервисный токен. Сервису нужны реальные данные для анализа.\n\nРазработчик начал создавать интеграцию\n\nНа этапе разработки: Тестовый токен — безопасно тестировать код. После завершения: Персональный токен — для работы с реальными данными.\n\nIT-⁠специалист изучает API\n\nНужен: Тестовый токен — можно экспериментировать без риска.\n\nПодключение 1С\n\nНужен: Персональный токен (если 1С локальная) или Сервисный (если облачная из Каталога решений). Тестовый не подходит — он не работает с реальными данными.\n\nКак создать тестовый токен\n\nСоздать тестовый токен может только владелец личного кабинета WB Партнёры.\n\nЗайдите в личный кабинет WB Партнёры\nНажмите на название организации → «Интеграции по API»\nНажмите «+ Создать токен»\nПерейдите на вкладку «Для интеграции вручную»\nВыберите «Тестовый токен»\nДобавьте комментарий (опционально), например: «Для разработчика Иванова»\nНажмите «Создать»\nНажмите «Скопировать и закрыть» — сохраните токен в надёжном месте\nОсобенности тестового токена\nСрок действия: 180 дней\nДоступ: Автоматически ко всем категориям песочницы\nРежим: Всегда чтение и запись\nИспользование: Только для тестовой среды\n\nТокен показывается только один раз при создании. Если потеряете — создайте новый.\n\nЧто такое песочница\n\nПесочница (sandbox) — изолированная тестовая среда с искусственными данными, полностью отделённая от вашего магазина. Тестовый токен работает только с песочницей.\n\nПодробнее о песочнице, доступных категориях и отличиях от боевой среды — в статье «Как работает песочница WB API». Конкретные ограничения по каждой категории, тестовые домены и нюансы — в статье «Ограничения тестового контура WB API».\n\nПереход от тестирования к реальной работе\nШаг 1. Создайте рабочий токен\n\nВ зависимости от ситуации: Сервисный, Персональный или Базовый. Если не уверены — воспользуйтесь статьёй «Облачный сервис или локальное решение».\n\nШаг 2. Замените токен в коде\n\nРазработчик заменяет тестовый токен на рабочий и тестовые домены (*-sandbox) на боевые.\n\nШаг 3. Проведите пилотное тестирование\n\nПроверьте несколько товаров или заказов, убедитесь, что всё работает.\n\nШаг 4. Запустите интеграцию\n\nПосле успешной проверки — полный запуск.\n\nШаг 5. Решите судьбу тестового токена\n\nЕсли разработка завершена — можно удалить. Если планируются обновления — сохраните.\n\nЧек-⁠лист перед запуском\n✓ Разработчик заменил тестовый токен на рабочий\n✓ Тестовые домены заменены на боевые\n✓ Интеграция проверена на нескольких реальных примерах\n✓ Учтены ограничения тестового контура (лимиты, асинхронность, объём данных)\n✓ Настроена обработка ошибок авторизации (401, 403)\n✓ Есть план действий на случай проблем\nЧастые вопросы\n\nМожно ли использовать тестовый токен для подключения сервиса из Каталога решений?\n\nСколько тестовых токенов можно создать?\n\nЧто будет, если дать тестовый токен вместо рабочего?\n\nМожно ли превратить тестовый токен в рабочий?"
