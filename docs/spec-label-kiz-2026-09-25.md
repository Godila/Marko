# Спека: «Этикетка КиЗ» — печать DataMatrix из справочника

Дата: 25.09.2026 · Статус: к проработке в свежей сессии (решение юзера) ·
Предыдущая фича: справочник идентификаторов WB (`1715b46`, в проде).

## Цель

Кнопка «Этикетка» у закреплённого sgtin в разделе «Идентификаторы WB» (и в блоке
«Закрепления sgtin» трассировки): скачать готовую к печати этикетку с DataMatrix
**полного** КиЗ. Сценарий юзера — «повторная поставка»: невыкуп вернулся, бирка
повреждена → перепечатать тот же код на ту же единицу и снова отгрузить.

## Доктрина источника (проверено 25.09)

- Полный КиЗ с криптохвостом (GS + AI 91/92) существует **только** в live-ответе
  `POST /api/marketplace/v3/orders/meta` (`metaDetails[key=sgtin].value`).
  Kv-кэш `wb_meta_cache` (TTL 10 мин) уже хранит его сырым — см.
  `marko/journal/identify.py: live_sgtins/_meta_cache_put`.
- Журнал/эксайз хранят `excise_short` — 31 символ **без** криптохвоста: для
  печати НЕ годится (сканер/касса проверяют крипточасть).
- Канонический альтернативный источник — PDF этикеток заказа эмиссии в СУЗ
  (кабинет, повторное скачивание); СУЗ-контур МАРКО не подключён.

## Параметры этикетки (wb-specs/seller-how-to-sell-kiz.txt)

DataMatrix 22×22 мм (лёгпром: наклейка 15,2–24,4 мм) · строго квадрат, без
искажений · однородный чёрный · 300 dpi · «Сглаживание» в драйвере принтера OFF ·
DataMatrix и баркод на одной стороне упаковки, с зазором. Перед отгрузкой
проверять «Честный ЗНАК.Бизнес» / «Чекмарк» (грейд верификатора ≥ 2 по ГОСТ;
смартфонная камера ненадёжна как критерий).

## Правовые рамки (WB-док прямо)

- «Повреждённый КИЗ приравнивается к отсутствию — маркировку нужно переделать»
  → перепечатка того же кода на ту же единицу штатна, статус/документы ЧЗ не меняются.
- На отгрузку код обязан быть «в обороте» (`decision=sgtinIntroduced`).
- Один КиЗ = один экземпляр товара; дублирование на другой товар — обход
  маркировки (WB ловит дубликаты при приёмке).
- Утеря бирки с неизвестным кодом — НЕ перепечатка: эмиссия нового КМ (СУЗ),
  старый висит в обороте до списания.

## Guard по decision (orders/meta)

- Разрешить: `sgtinIntroduced`, `filled`, `sgtinSoldB2B`, `deadlineExceeded` (с пояснением).
- Блокировать: `sgtinRetired`, `sgtinWrittenOff` (этикетка мертва), `sgtinNotFound`.
- Hint у кнопки: «один код = один экземпляр товара».

## Открытые вопросы (решить в свежей сессии)

1. **Рендер DataMatrix**: treepoem (pip, PNG) vs bwip-js (фронт; но `App.jsx` —
   монолит с 0 зависимостей кроме React) vs pylibdmtx (libdmtx). У каждого
   сверить GS1-режим и честный ASCII 29 (`\x1D`) в разделителях — главная
   причина битых самодельных этикеток.
2. **Формат вывода**: одиночный PNG 300 dpi vs PDF-раскладка (A4 × N наклеек)
   vs ZPL для термо-принтеров — спросить юзера, чем печатает.
3. **Где генерить**: бэкенд-эндпоинт (принимает sgtin, отдаёт файл) vs фронт
   (sgtin уже есть в ответе `/v1/identify`).
4. **Персист полного sgtin** сверх 10 мин кэша — пока не нужен (live 300/мин
   дёшев); история перепечаток может попросить позже.
5. **Golden-тест**: roundtrip — закодировать → декодировать (pylibdmtx/zxing)
   → байт-в-байт совпал sgtin включая GS. Это главный тест качества.
6. Опционально: прятать кнопку для «чужих» GTIN (не из нашего НК).
