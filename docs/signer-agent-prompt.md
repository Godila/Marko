# Промпт для AI-ассистента на закрытой VM: signer-агент MP-GIS_MT

## ТЕКСТ ПРОМПТА

Ты работаешь на закрытой машине (Windows Server, установлен КриптоПро, действующая УКЭП; реализация подписи — на твоё усмотрение, исходя из того, что есть на машине).

## Цель

Напиши и настрой **signer-агент** — резидентный процесс, который:

1. забирает из очереди платформы MP-GIS_MT задачи на подписание (исходящие HTTPS, долгий опрос);
2. подписывает данные УКЭП по ГОСТ Р 34.10-2012;
3. возвращает платформе результат подписи в base64.

Готовность: платформа получает валидные подписи обоих типов; агент устойчиво работает автономно (переживает недоступность платформы и перезагрузку машины) и не требует постоянного внимания.

## Границы

- Машина принимает только исходящие соединения. Приватный ключ и сертификат не покидают машину.
- Агент общается только с платформой MP-GIS_MT. Это НЕ клиент Честного знака — всё, что связано с ЧЗ, делает платформа.
- В логи не должны попадать секреты (токен, содержимое подписываемых данных).

## Контракт API платформы

База: `https://gis.adel-factory.ru`. Все запросы — заголовок `Authorization: Bearer <SIGNER_TOKEN>` (статический токен, выдан владельцем; передаётся в конфигурации агента).

### Очередь

`POST /v1/sign/lease`
- Тело: `{}`. Таймаут клиента: 35 с (сервер держит соединение до 30 с).
- `200` → задача выдана в аренду на 120 с:
  ```json
  {"task_id": "<id>", "type": "auth_sign" | "doc_sign", "payload": {...}}
  ```
- `204` — задач нет; следующий опрос.
- `401` — неверный SIGNER_TOKEN (ждать 30 с, продолжать).
- `5xx`/таймаут — пауза 5 с, продолжать.
- Пока агент регулярно делает lease-запросы, он считается живым (отдельный heartbeat не нужен; платформа сигнализирует, если опросов нет > 2 часов).

### Результат

`POST /v1/sign/results`
- Успех: `{"task_id": "<id>", "signature_b64": "<base64 подписи>"}`.
- Не удалось подписать: `{"task_id": "<id>", "error": "<короткое описание>"}` (локальные ретраи подписи не нужны — платформа решает сама).
- `200` — принято; `404` (аренда истекла) и `409` (дубликат) — игнорировать.

### Типы задач и требуемые подписи

- `auth_sign`: payload `{"data": "<строка>"}`. Подписать байты строки (UTF-8) **присоединённой** подписью CMS/CAdES-BES по ГОСТ. Результат — base64 одной строкой (без переносов).
- `doc_sign`: payload `{"data_b64": "<base64 бинарных данных>"}`. Подписать бинарные данные **откреплённой** (detached) подписью CMS/CAdES-BES по ГОСТ. Результат — base64 откреплённой подписи.

### Проверка связи

- `GET /healthz` (без авторизации) — статус платформы.
- `GET /v1/sign/ping` с Bearer-токеном — `{"ok": true}` при валидном SIGNER_TOKEN. Используй для проверки связности до того, как в очереди появятся задачи.
- Сквозной тест: задачи в очередь кладёт платформа либо владелец (тестовые — через админский эндпоинт `POST /v1/sign/test-task`, недоступный тебе). Для отладки полного цикла попроси владельца создать тестовую задачу (`{"type":"auth_sign","data":"MPMT-SIGNER-TEST"}` или `{"type":"doc_sign","data_b64":"..."}`) — твой следующий `lease` её получит; после твоего `results` владелец увидит статус задачи `done`/`error` и подтвердит.

