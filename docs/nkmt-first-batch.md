## 0. Подготовка (однократно)

- [ ] **Реестр деклараций**: блок «Декларации» (или `POST /v1/nkmt/declarations`
      `{doc_number, doc_date, doc_type: "declaration", title}`) — внести текущую
      действующую декларацию о соответствии. Из реестра она подставляется
      дефолтом в атрибут 23557 («номер:::дата») первого же фида.
- [ ] **Дефолты**: блок «Дефолты» (или `GET/PUT /v1/nkmt/defaults`, kv `nk_defaults`)
      — заполнить: бренд (YCPB|ADEL|…), техрегламент (ТР ТС 017/2011 «О безопасности
      продукции легкой промышленности»), целевой пол, размерная система
      (МЕЖДУНАРОДНЫЙ), страна, производитель, декларация. Дефолты применяются
      к пустым ячейкам xlsx и фиксируются в карточке (прозрачно).
- [ ] **Шаблон xlsx** (12–13 колонок, смешанные ТН ВЭД в одном файле):
      `ТН ВЭД* (10 цифр) | наименование* | вид товара* | цвет* | состав* | размер* |
      модель/артикул | бренд | целевой пол | размерная система | декларация |
      категория (опц., только если по ТН ВЭД несколько категорий)`.
      `*` — обязательные (пустое заполняется дефолтом, если он есть).
      Колонка `gtin` в нашем шаблоне НЕ предусмотрена: 99% кодов генерируются
      платформой через `/nk/generate-gtins` (прод-лимит 11000/мес, usage виден
      в стате батча после подачи).

## 1. Импорт → проверка карточек

- [ ] «Импорт» xlsx (или `POST /v1/nkmt/import`, multipart) → создаётся батч:
      статус `new` (все строки ok) или `partial` (есть ошибки).
- [ ] Открыть батч, проверить каждую строку: статус `ok` или `error` с
      `error_text` (формат, обязательные, preset'ы вида товара/цвета,
      размерная система, бренд, РД, категория, дедуп артикула/gtin).
- [ ] Если есть `error`: поправить xlsx, **реимпорт того же файла** — те же
      артикулы обновляются на месте (upsert), карточка переезжает в новый батч.
      Дальше — только когда все строки `ok`.

## 2. Подать (feed) → модерация → авто-подпись

- [ ] «Подать» (или `POST /v1/nkmt/batches/{id}/feed`): платформа генерирует
      GTIN для строк без кода, подаёт `/nk/feed` (чанки ≤500, `moderation:1`
      в каждой entry — сразу на модерацию, не черновиком) → `batch.feed_id`,
      карточки → `fed`, батч → `moderation`.
- [ ] Ждать `Moderated`: воркер опрашивает раз в 10 минут; вручную — кнопка
      «Обновить» (`POST .../refresh`). Статусы фида по пути: `Received` →
      `Processing` → `Moderated`.
- [ ] После `Moderated` воркер сам подписывает: получает xml карточек
      (`/nk/feed-product-document`), подписывает нашим signer-агентом
      (doc_sign, CAdES) и отправляет `/nk/feed-product-sign-pkcs` →
      карточки `published`, батч `published`. Ручной дубль — кнопка
      «Подписать» (`POST .../sign`).
- [ ] Финальные статусы приходят TG-уведомлением.

## 3. Результат

- [ ] «Отчёт» (`GET /v1/nkmt/batches/{id}/report`) → xlsx для 1С, две колонки
      «GTIN | Наименование» (только `published`-карточки; `?format=csv` — опция).
- [ ] Визуальная проверка в ЛК НК (нац-каталог.рф): карточки первого батча
      опубликованы, атрибуты/бренд/декларация на месте.

## Если что-то пошло не так

**Статусы батча**: `new`/`partial` (импорт) → `moderation` → `signing` →
`published` | `error` (Rejected фида). **Статусы карточек**:
`ok` → `fed` → `moderation` → `notsigned` → `signing` → `published`;
ошибочные: `error` (импорт), `errors` (Rejected фида), `error_sign`
(подписание). Причина всегда в `error_text` карточки (UI и API).

Типовые ситуации:

- **Ошибки импорта** (`error`-строки): поправить xlsx, реимпорт — те же
  артикулы обновятся (upsert), `good_id`/непустой `gtin` сохраняются.
- **Фид завис в `Processing` > 24 ч**: предполагаем, что НК сам переведёт
  его в `Rejected` (допущение, непроверено) — «Обновить» покажет. Дальше:
  исправить xlsx → повторный импорт (создаст НОВЫЙ батч) → «Подать» на
  новом батче. Старый батч остаётся в `moderation`/`error` — «Подать» на
  нём вернёт 409 (статус уже не feedable).
- **`error_sign`**: посмотреть `error_text` («не получен xml карточки» /
  сообщение НК по goodId / ошибка signer-агента). Кнопка «Подписать»
  берёт в повторную попытку и `notsigned`, и `error_sign`-карточки
  (старый `error_text` при этом сбрасывается).
- **Rejected модерации**: `error_text` карточек содержит позиционную ошибку
  фида; правка xlsx → реимпорт → новая подача.

REST-эндпоинты (scopes: запись `nkmt:import`, чтение `read`):

| Метод | Назначение |
|---|---|

| `GET /v1/nkmt/batches[?status=]` | список батчей |
| `GET /v1/nkmt/batches/{id}[?card_status=]` | батч + карточки (с `error_text`) |
| `POST /v1/nkmt/batches/{id}/feed` | подача (generate-gtins + feed) |
| `POST /v1/nkmt/batches/{id}/refresh` | пересинка статусов модерации |

| `GET /v1/nkmt/batches/{id}/report` | отчёт для 1С (xlsx, `?format=csv`) |
| `GET/POST/DELETE /v1/nkmt/declarations[/{id}]` | реестр РД |
| `GET/PUT /v1/nkmt/defaults` | дефолты платформы |
