# Фаза 4 (старт): вывод-фикс + контроль возвратов WB FBS

2026-09-04. Решение юзера: «контроль + кнопка» — платформа следит за возвратами WB
(список, дедлайн забора 7 дней), готовит LP_RETURN драфт; подача в ЧЗ — кнопкой.
Регламентный фундамент: `crpt-specs/returns-discovery-2026-09-04.md`.

## Цель

1. **Критичный фикс (до первой продажи)**: эмиттер LK_RECEIPT подставляет `fias_id`
   (МОД) и `primary_document_custom_name` (при document_type=OTHER). Без fias_id прод
   отклоняет документ (доказано 04.09). Источник значения — kv `emitter_defaults`
   (editable через REST/UI), стартовое значение прод-ФИАС задаётся при деплое.
2. **Монитор возвратов WB**: ежечасный поллинг
   `GET /api/v1/analytics/goods-return` (окно 7 дней; квота базового токена 2/час),
   хранение строк (уникальность по srid возврата, КМ в отчёте нет), REST-список,
   TG-алерт на новый возврат и на дедлайн забора ≤48 ч (дедуп per srid).
3. **UI «Возвраты»**: таблица возвратов WB (статус, готовность, дедлайн — красным при
   ≤48 ч), ручной «Обновить», кнопка «Собрать возврат» (существующий батч-эндпоинт)
   и последние LP_RETURN-документы с кнопкой «Подать».

## Контракты

- `withdraw_batch` payload: `fias_id` — только если задан в kv; при `document_type=OTHER`
  обязателен `primary_document_custom_name` (kv-дефолт или константа-фолбэк).
- `GET/PUT /v1/emitter/defaults` (kv `emitter_defaults`): `{fias_id, primary_custom_name}`.
- `WBClient.goods_return(date_from, date_to)` — гейт 2/час по kv-штампам (паттерн excise).
- Инжест возвратов: UPSERT по `srid` (статус/даты обновляются, новые — insert);
  событие «новый возврат» и «дедлайн близко» — TG (send без кредов = no-op).
- Migration 0007: таблица `wb.returns` (srid PK, статус, даты, json-строка отчёта).
- Скоупы REST: чтение — `read`; поллинг/дефолты PUT — `docs:submit`.

## Вне Scope

Автоподача LP_RETURN; перемаркировка (LK_REMARK + СУЗ REMARK) — вручную через ЛК ЧЗ;
claims-api; справочник «WB-склад → ФИАС» (один МОД).

## Задачи

1. Эмиттер: kv-дефолты + fias_id/custom_name в payload + тесты + REST дефолтов.
2. WB: goods_return() с гейтом, модель+миграция, ingest/poll, worker-луп, тесты.
3. REST /v1/wb/returns (+ /poll), тесты API (read-скоуп, поллинг — docs:submit).
4. UI: вкладка «Возвраты».
5. Полный сьют (сериализованно), коммиты, деплой, seed kv на проде, healthz.
